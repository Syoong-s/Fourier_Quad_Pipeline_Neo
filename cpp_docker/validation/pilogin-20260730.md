# pilogin 单 SIF 验证记录（2026-07-30）

## 验证范围

本记录验证同一个预编译 SIF 在 x86_64 Slurm 集群上的通用 PMI2 启动路径：

`srun --mpi=pmi2` → `apptainer exec --cleanenv` → SIF 内 OpenMPI 4.1.8。

pilogin 是验证站点，不对应单独的 Docker target、Pixi environment、镜像
tag 或 runner。验证工作区位于 `~/ysx/Agents/cpppipeline-portable`，日志
位于 `~/ysx/Agents/outputs`。

## 失败门槛与修复

首轮 SIF `60088222` 和编译 `60088635` 成功，但 smoke `60088685` 在
`MPI_Init` 失败。该镜像包含 PMI2，却未构建 OpenMPI 的 Slurm 环境识别
组件。

同一镜像定义随后增加 `--with-slurm`，并以 `MCA schizo: slurm` 作为硬
断言；`--with-pmi=/opt/pmi2` 保持不变。失败 archive、SIF、sidecar 与
runner 使用带 `noslurm-60088685` 的名称保留。修复没有引入第二个镜像、
宿主 MPI 或宿主 `mpirun`。

## 结论与边界

最终单 SIF 已在 pilogin 完成构建、完整 cpp_Standard 编译、单节点 PMI2
和双节点 PMI2 验证。可移植支持契约是 x86_64 Linux、Slurm 暴露 PMI2、
Apptainer/Singularity 和跨节点共享文件系统。

这次结果不等于已验证 ARM、PBS/LSF、只提供 PMIx 的 Slurm，或
UCX/OFI/InfiniBand vendor fabric 加速。真实科学 pipeline 运行前仍需把
站点数据 bind 目标与 `LensingConfig.hpp` 中的科学路径配置对齐。
